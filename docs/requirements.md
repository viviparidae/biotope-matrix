# アジャイル型要求仕様書

## 1. ユーザーストーリーとスコープ

観察者（ユーザー）として、数ピクセルで描かれた無数の生物たちが蠢く画面上で、地形の変貌・災害の連鎖・自動生成される環境音が相互に影響し合うピタゴラスイッチ的な生態系を、操作を強制されずに眺めて楽しみたい。

対象は草、草食個体、肉食個体、死骸、分解者、地形、環境、災害、サウンドの自律シミュレーション、極小ドット描画、Kubernetes上のWorkerスケーリングと環境設定配布とする。草食個体の視野は5px、肉食個体の視野は100pxとする。

## 2. 機能要求（Gherkin）

### Feature F-01: 草の生成と自然枯死
```gherkin
Feature: 草の生成と自然枯死
  Scenario: 草の上限未満で草を生成する
    Given 草が100株未満で、草の発生可能な明るさである
    When 1秒ごとの生成判定が発生条件を満たす
    Then ランダムな座標に草を1株生成する
  Scenario: 草を自然枯死させる
    Given 草の発生から30秒経過している
    When 草が捕食されていない
    Then 草を消滅させる
```

### Feature F-02: 草食個体の採餌と分裂
```gherkin
Feature: 草食個体の採餌と分裂
  Scenario: 近くの草を検知して移動する
    Given 草食個体の半径5px以内に草がある
    When 行動を更新する
    Then 最も近い草に向かって移動する
  Scenario: 草を食べて回復する
    Given 草食個体が草に接触している
    When 捕食処理を実行する
    Then 草を消滅させ、エネルギーを50増加させる
  Scenario: 高エネルギーで分裂する
    Given エネルギーが150を超えている
    When 分裂処理を実行する
    Then 親と子のエネルギーを75ずつにし、子を1体生成する
```

### Feature F-03: 肉食個体の追尾と捕食
```gherkin
Feature: 肉食個体の追尾と捕食
  Scenario: 最も近い草食個体を追尾する
    Given 半径100px以内に草食個体がいる
    When 行動を更新する
    Then 最も近い草食個体を追尾する
  Scenario: 草食個体を捕食する
    Given 肉食個体が草食個体に接触している
    When 捕食処理を実行する
    Then 草食個体を死亡させ、死骸を生成し、エネルギーを100増加させる
  Scenario: 獲物がいないとき徘徊する
    Given 視野内に草食個体がいない
    When 行動を更新する
    Then ランダムな方向へ徘徊する
```

### Feature F-04: 遺伝、環境適応、境界反射
```gherkin
Feature: 個体パラメータの遺伝と環境適応
  Scenario: 分裂時に突然変異させる
    Given 個体が子個体を生成する
    When 子の速度と視野を決定する
    Then 親を基準に各値を±10%の範囲で変化させる
  Scenario: 速度に応じて消費を変える
    Given 速度の異なる個体がいる
    When 毎フレームの消費を計算する
    Then 速い個体ほど消費を増やし、遅い個体ほど減らす
  Scenario: 画面端で反射させる
    Given 個体が上下左右の端に接触する
    When 移動を更新する
    Then 接触した軸の移動ベクトルを反転する
```

### Feature F-05: 個体数制御と連鎖
```gherkin
Feature: 生態系の個体数制御と連鎖イベント
  Scenario: 肉食個体絶滅時に補充する
    Given 肉食個体が0体で草食個体が30体を超えている
    When 補充タイマーが発火する
    Then 画面外または端から肉食個体を1体生成する
  Scenario: 大繁殖モードを開始する
    Given 草食個体が50体に到達する
    When 条件発生を処理する
    Then 草の成長速度を一時的に3倍にする
  Scenario: 大繁殖から捕食者増加へ連鎖する
    Given 草と草食個体が急増している
    When 連鎖反応を処理する
    Then 巨大または大量の肉食個体を生成する
  Scenario: 捕食後に初期状態へ収束する
    Given 捕食者が草食個体をほぼ喰い尽くしている
    When 個体数と環境状態を更新する
    Then 崩壊寸前まで減少させ、初期状態へ遷移する
```

### Feature F-06: 明るさと温度
```gherkin
Feature: 環境要因による生態系の変化
  Scenario: 夜間の環境を適用する
    Given 明るさが低下して夜になっている
    When 環境を適用する
    Then 草の発生を停止し、個体の視野を50%にする
  Scenario: 低温の環境を適用する
    Given 気温が10℃未満である
    When 環境を適用する
    Then 移動速度を30%低下させ、体温維持分の消費を増やす
```

### Feature F-07: 死骸、分解者、土壌栄養
```gherkin
Feature: 死骸と分解による物質循環
  Scenario: 個体の死亡時に死骸を残す
    Given 草食個体または肉食個体が死亡する
    When 死亡処理を実行する
    Then 死亡地点に死骸を生成する
  Scenario: 分解で栄養度を上げる
    Given 死骸がフィールド上にある
    When 分解処理を進める
    Then 分解者エフェクトを発生させ、死骸を消化し、栄養度を上げる
  Scenario: 分解後も高栄養エリアを維持する
    Given 死骸の分解が完了している
    When フィールドを更新する
    Then エフェクトを残し、高栄養エリアに草を高密度生成する
  Scenario: 排泄物を栄養へ戻す
    Given 個体が生存している
    When 個体が排泄し、排泄物の分解が完了する
    Then 排泄物の栄養を土壌へ戻す
```

### Feature F-08: 地形改変と災害
```gherkin
Feature: 地形改変と災害のドミノ倒し
  Scenario: 草を食べ尽くした場所を砂漠化する
    Given 同じエリアの草を食べ尽くしている
    When 地形改変条件を評価する
    Then 砂漠に変更し、移動速度を低下させる
  Scenario: 分解者が滞留した場所を湿地化する
    Given 分解者エフェクトが一定時間留まっている
    When 地形改変条件を評価する
    Then 湿地に変更し、草生長率を10倍にする
  Scenario: 捕食集中地点を山へ変える
    Given 同じ場所で捕食が集中している
    When 地形改変条件を評価する
    Then 山を隆起させ、移動不能な壁にする
  Scenario: 隕石、水流、ゾンビ化を処理する
    Given 個体数、湿度、分解者密度のいずれかが閾値を超えている
    When 災害トリガーを処理する
    Then クレーターと死骸、水流によるシャッフル、または紫色ゾンビを生成する
```

### Feature F-09: 描画とサウンド
```gherkin
Feature: 極小ドット描画と環境音
  Scenario: 生物を極小ドットで描画する
    Given 個体または草が存在する
    When 画面を描画する
    Then 生物を1x1〜3x3pxで描き、草食は緑2px、肉食は赤3pxにする
  Scenario: 変異を視覚化する
    Given 速度または視野の変異がある
    When 画面を描画する
    Then 色相、形状、点滅パターンの差として表現する
  Scenario: 位置と状態を効果音に反映する
    Given 移動または捕食が発生する
    When サウンドイベントを処理する
    Then Web Audio APIで生成し、左右位置をパン、状態をピッチに反映する
  Scenario: 状態に応じて音楽性を遷移する
    Given 生態系が安定、または大繁殖・災害中である
    When 環境音を更新する
    Then チルな和音、または速い不協和音へ遷移する
```

### Feature F-10: Kubernetesオーケストレーション
```gherkin
Feature: インフラによるシミュレーションのオーケストレーション
  Scenario: Worker Podをスケールアウトする
    Given Pod内の個体数またはCPU負荷が80%を超えている
    When HPAまたはKEDAが評価する
    Then Worker Podを自動的にスケールアウトする
  Scenario: 全Podへ環境設定を適用する
    Given 明るさまたは温度がCRDまたはConfigMapで更新される
    When Kubernetesが設定変更を配布する
    Then 全Worker Podへ適用し、シミュレーションへ反映する
```

## 3. 非機能要求（品質シナリオ）

| ID | 品質特性 | 刺激 | 応答・測定基準 |
| --- | --- | --- | --- |
| NFR-01 | 性能 | 個体・草・エフェクトが増加 | 平均30 FPS以上、95パーセンタイル33ms以下で更新・描画 |
| NFR-02 | 応答性 | 観察画面を開く | 初期表示開始3秒以内 |
| NFR-03 | 安定性 | 24時間連続実行 | 異常終了0回、メモリの継続増加なし |
| NFR-04 | 可観測性 | 個体数・負荷・環境・災害が変化 | 主要メトリクスと構造化ログを観測可能 |
| NFR-05 | スケーラビリティ | 個体数またはCPUが80%超過 | 設定周期内にHPA/KEDAがスケール開始 |
| NFR-06 | 一貫性 | CRD/ConfigMap更新 | 全Podの環境値が一致 |
| NFR-07 | 復旧性 | Worker停止・再起動 | 設定した復旧時間内にReady、状態から再開 |
| NFR-08 | 互換性 | 対応ブラウザ表示・音声拒否 | Chromium・Firefox・Safari系で描画継続 |
| NFR-09 | セキュリティ | 不正な設定・通信 | 未認証変更0件、入力検証エラーを記録 |
| NFR-10 | 保守性 | ルール・閾値変更 | Feature単位の自動テストが可能 |
| NFR-11 | アクセシビリティ | 音声を使えない | 種別・地形・災害を視覚的に判別可能 |
| NFR-12 | データ整合性 | 複数イベントが同一tickに発生 | 総数と資源収支が二重計上なく一致 |

## 4. 受け入れ方針

- 各Gherkinシナリオを自動テストまたは再現可能なシミュレーションテストにする。
- ルールごとのイベントログで連鎖の発生順序を検証可能にする。
- 未指定の閾値は設定値として外部化し、初期値と単位を実装前に合意する。
- 外部APIやKubernetesを利用できない環境では代替表示またはローカルモックで検証する。
